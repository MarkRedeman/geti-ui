# Segment Anything (ONNX)

Segment Anything in this package exposes encoder/decoder flows via a wrapper.

## Imports

```ts
import {
    buildSegmentAnythingInstance,
    parseEncoding,
    SegmentAnythingModels,
} from '@geti-ui/smart-tools/segment-anything';
```

## Example

```ts
const sam = await buildSegmentAnythingInstance();

await sam.init('SEGMENT_ANYTHING_ENCODER');
const encoding = await sam.processEncoder(imageData);

await sam.init('SEGMENT_ANYTHING_DECODER');
const result = await sam.processDecoder(encoding, {
    points: [{ x: 150, y: 200, positive: true }],
    boxes: [],
});
```

## Server-side encoding

Encoding is the expensive half of the flow. If a server computes the image embedding for
you, skip `init('SEGMENT_ANYTHING_ENCODER')` and `processEncoder` entirely and hand the
downloaded payload to `parseEncoding` instead — the decoder does not care where the
embedding came from.

```ts
const response = await fetch(embeddingUrl);
const encoding = parseEncoding(await response.arrayBuffer());

const sam = await buildSegmentAnythingInstance();
await sam.init('SEGMENT_ANYTHING_DECODER');
const result = await sam.processDecoder(encoding, {
    points: [{ x: 150, y: 200, positive: true }],
    boxes: [],
});
```

`parseEncoding` expects a [safetensors](https://github.com/huggingface/safetensors) buffer
containing an `image_embeddings` tensor of shape `[1, 256, 64, 64]` and dtype `F32`, plus a
`__metadata__` section with `original_width`, `original_height`, `new_width` and
`new_height`. The `new_*` values are the resized, pre-pad dimensions the decoder uses to
scale prompt coordinates, so the server must resize the longest side to 1024 exactly as
the local encoder does. Anything that does not match this contract throws an
`InvalidEncodingError`.
